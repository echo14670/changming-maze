# 实验四 · 游戏方向方案 v2（3D 迷宫版）

> 5 人小组｜2026-11-15 起｜答辩 2026-12-05（第 14 周周六）
> **设计原则：游戏性做减法，图形学做加法。**
> 流程简化为“第一人称 3D 走迷宫 + 收集 3 枚火种 + 回中央灯塔大门交互 + 镜头自动拉远看全景”，不做战斗、不做复杂谜题、不做 NPC；省下的时间全部投到光照、阴影、材质、体积光、水面、粒子、后期和性能上。
> 排期仍按工作区三份周报模板组织，表格可直接粘进 docx。

## 一、推荐结论

**《长明：雾海迷宫》——第一人称 3D 迷宫探索，8~12 分钟。**

> 灯塔矗立在礁岛中央，四周是环塔而建的露天石阵迷宫。风暴夜，主灯熄灭，三枚火种散落在石阵四区。学徒提灯进入石阵，找回火种，回到中央灯塔大门，把火种送入主灯；光束穿透雾海后，镜头自动脱离第一人称、拉远展示灯塔、石阵、海岛与大海，游戏结束。

这不是“解谜游戏”，而是**一个用迷宫承载图形学展示的 3D 场景**：

- 迷宫负责“路线、节奏、探索感”，不负责“烧脑”；
- 玩家只做四件事：走、看、捡火种、回中央灯塔大门交互；
- 交互后不再需要操作：火种升入主灯 → 光束穿透雾海 → 镜头自动拉远到海岛全景 → 游戏结束；
- 没有战斗、没有死亡惩罚、没有对话树、没有多结局；
- 所有“游戏性预算”换成图形学预算：程序化迷宫、PBR 材质、动态阴影、体积光、水面、雨、粒子、后期、性能优化。

## 二、游戏设计（简化版）

### 2.1 故事与目标

灯塔矗立在礁岛中央，四周是环塔而建的露天石阵迷宫。风暴夜，主灯熄灭，三枚火种被冲散在石阵四处。学徒提灯进入石阵，找回火种，回到中央灯塔大门。

- **开始**：石阵入口，一盏小灯，一张会被迷雾遮住的小地图；
- **探索**：在四个区域中寻找三枚发光的火种，沿途看到外庭、水院、烬厅、中庭；
- **回归**：集齐三枚火种，中央灯塔大门亮起，玩家沿原路或回路返回中庭；
- **结尾**：在灯塔大门交互，三枚火种化作光点升入塔顶主灯；主灯点燃，光束穿透雾海；镜头自动脱离第一人称，从中央光井升起、拉远，展示灯塔、环塔石阵、海岛与大海；游戏结束。

> 结尾不再需要玩家操作，也不再做额外的解谜或对话——**收集齐 → 回大门 → 交互 → 看镜头拉远**，流程到此为止。

> 背景意义：以沿海灯塔守塔人为原型，“守灯”象征责任与传承；迷宫是“试炼”，灯是“归途”。

### 2.2 核心流程

```
入口 → 探索四个区域 → 找到 3 枚火种（各在远处死角）
     → 回到中央灯塔大门 → 按 E 交互
     → 火种升入主灯 → 光束穿透雾海 → 镜头自动拉远 → 全景 → 结束
```

- 单局 8~12 分钟；
- 火种位置由种子决定，但保证分布在不同象限；
- 小地图只显示走过区域，火种靠近后才会标记；
- 没有失败：掉进水里/卡住按 `R` 回到最近检查点；
- 计时器默认关闭，只在 HUD 里显示“探索度/用时”，用于报告数据；
- 交互后进入 `ending` 状态：禁用输入、隐藏 HUD、镜头由脚本接管，不再回到第一人称；
- 未集齐 3 枚时与大门交互只提示“还差 N 枚火种”，不触发结局。

### 2.3 迷宫规格

| 项 | 规格 |
| --- | --- |
| 网格 | 15×15 格（第二周定稿） |
| 单元格 | 4m × 4m |
| 墙高 | 4.5m，墙厚 0.6m |
| 生成 | 递归回溯（DFS）生成完美迷宫，再随机拆 12% 墙形成回路 |
| 种子 | URL `?seed=20261205` 或界面输入，保证答辩可复现 |
| 形式 | 露天环塔石阵，中央是灯塔；无顶棚，中央留光井，结局镜头可从上方升起 |
| 区域 | 四个象限四种材质/灯光：外庭（石）、水院（水/苔）、烬厅（砖/火）、中庭（大理石/金） |
| 地标 | 方尖碑、断拱、巨灯、石像，用于辨向 |
| 中庭 | 中央 3×3 格，抬高 0.6m，五级台阶；灯塔基座与大门；塔顶主灯；上方光井 |
| 水 | 水院区域水道深 0.15m，水面低于地面 |
| 外景 | 礁岛、灯塔外立面、外海、远处船灯（结局拉远用） |
| 火种 | 3 枚，放在远离入口的死角，带发光与粒子 |

> 与实验三的衔接：实验三已经做过 DFS 树篱迷宫，这次把它升级为“有高度、有材质、有灯光、可第一人称漫游”的 3D 石迷宫——报告里可以作为技术演进讲。

### 2.4 操作与 HUD

| 输入 | 功能 |
| --- | --- |
| `W A S D` | 移动 |
| 鼠标 | 环视（Pointer Lock；若被拦则按住拖动） |
| `Shift` | 快走 |
| `E` | 拾取火种 / 与灯塔大门交互（集齐 3 枚后触发结局） |
| `M` | 放大小地图 |
| `Tab` | 设置 / 画质 / 种子 |
| `R` | 回到最近检查点（长按） |
| `Esc` | 暂停 |

HUD：火种 0/3、探索度、小地图（迷雾）、交互提示、当前区域名、帧率/画质（调试）。
小地图用 Canvas 2D 叠加，不占 WebGL 管线。
结局镜头期间输入禁用、HUD 淡出；按 `Esc` 可在 2 秒后跳过到标题/制作名单（答辩演示可不跳）。

### 2.5 难度与失败

- 没有敌人、没有血量、没有时间限制；
- 迷路超过 90 秒，HUD 给一个指向最近未收集火种的淡箭头（可关）；
- 落水/卡住 → `R` 回检查点；
- 目标只有一个：集齐 3 枚火种，回到中央灯塔大门交互，观看结局；
- 交互后没有额外操作，镜头拉远、标题出现即结束。

### 2.6 结局镜头（12~15 秒）

| 时间 | 画面 | 技术 |
| --- | --- | --- |
| 0.0–1.5s | 玩家站在灯塔大门前按 `E`；HUD 淡出，三枚火种从身边浮起 | 输入锁定；火种粒子沿螺旋线上升 |
| 1.5–3.0s | 火种进入塔顶主灯，主灯点燃，光束穿透雾海；轻微震屏/闪光 | 主灯 emissive 拉高；体积光束强度渐变；Bloom |
| 3.0–8.0s | 镜头脱离第一人称，沿中央光井垂直升起，俯视环塔石阵 | Catmull-Rom 位置曲线 + 注视点曲线；FOV 60→45 |
| 8.0–12.0s | 镜头继续拉远并绕塔，灯塔、石阵、礁岛、外海、远处船灯同框 | 外景/海面 LOD 切换；远景雾；船灯点精灵 |
| 12.0–15.0s | 光束扫过海面，画面淡出，出现标题《长明》与制作名单 | letterbox；标题/重开按钮；雨声淡出 |

**关键点**：

- 镜头路径必须经过中央光井，避免穿墙；5 个控制点逐段验收；
- 拉远后要能看清“迷宫图案 + 灯塔 + 大海”三层信息，这是全片最重要的一个镜头；
- 结束后不再回到第一人称；只提供“重新开始/制作名单”按钮；
- 答辩时这一段完整播放，不跳过。

## 三、图形学能力清单（不阉割）

> 这是本方案的“验收单”。游戏性可以砍，下面这些**一项都不能少**；每项都要有开关/对比截图，答辩时能现场演示。

| # | 能力 | 实现方式 | 验收标准 | 负责 |
| --- | --- | --- | --- | --- |
| 1 | 程序化迷宫几何 | DFS 生成 + 墙体按材质合并 BufferGeometry | 15×15 迷宫一次生成；迷宫批次 draw call ≤ 40 | B |
| 2 | 程序化 PBR 纹理 | Canvas/噪声生成石、苔、砖、木、水法线；1K | 四种墙面材质肉眼可分；有法线细节 | E |
| 3 | 三类光源 + 光照模型 | 月光平行光 + 灯笼聚光 + 火盆点光；PBR/Blinn-Phong 可切 | 三种光同时可见；切换模型有差异 | C |
| 4 | 阴影贴图 | 2048 深度图 + 3×3 PCF；灯笼动态阴影 | 灯笼移动时影子跟着动；无明显 acne | C |
| 5 | 体积雾/光柱 | 指数高度雾 + 聚光灯锥体射线步进/径向模糊 | 灯下有可见光柱；可开关对比 | C |
| 6 | 水面 | Gerstner 波 + 法线扰动 + 简化反射/折射 | 水面有波纹、能映出灯火；可开关 | C |
| 7 | 雨/水滴/火星粒子 | 实例化雨柱 + 地面涟漪 + 火盆火星 | 水院有雨、烬厅有火星 | C |
| 8 | HDR + 后期 | RGBA16F + Bloom + ACES + 暗角/颗粒 | 火种/主灯有辉光；画面不发灰 | C |
| 9 | glTF 模型加载 | CC0 道具 GLB → Base64 → `GLTFLoader.parse` | 石像/木箱/沉船等道具正常显示 | A/B |
| 10 | 动画 | 灯火摇曳、灯塔大门开启、火种升空、浮尘、水面流动 | 主灯点亮有演出；大门有开启动画 | B/C |
| 11 | 性能工程 | 实例化、合批、视锥剔除、LOD、画质档 | 1440×900 独显 60fps；集显 30fps | A |
| 12 | 第一人称相机 | 指针锁定/拖动、头部微晃、碰撞、台阶 | 贴墙不穿模；上下台阶顺滑 | D |
| 13 | 小地图/迷雾 | Canvas 2D、探索格记录、火种标记 | 走过区域点亮；火种靠近才显示 | D |
| 14 | 诊断与自动化 | `window.changming` API + Playwright | 一键跳区域/集火种/触发结局/截图；控制台零 error | D/E |
| 15 | 结局电影相机 | `ending` 状态机 + Catmull-Rom 位置/目标双曲线 + smoothstep；FOV 60→45；HUD 淡出/letterbox | 集齐 3 枚交互后 12~15 秒自动拉远；镜头离开第一人称，掠过石阵、灯塔、海岛、海面；不穿墙 | D/A |
| 16 | 岛屿外景与海面全景 | 灯塔外立面、露天石阵俯视、外海 Gerstner 波、远处船灯、远景雾 | 拉远后能看到完整灯塔 + 石阵 + 大海；海面有波光与船灯 | B/C |

**答辩现场**：设置面板里给每个图形特性一个开关（阴影/体积光/水面/雨/后期/PBR），一键切换；最后完整跑一次“集齐 → 大门交互 → 镜头拉远”，这是本方案最重要的 15 秒。

## 四、技术方案

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 渲染 | three.js（锁定版本，本地打包） | PBR、阴影、后处理、加载器成熟 |
| 构建 | esbuild → IIFE | 新版 three.js 只有 ESM，`file://` 直接 import 会被 CORS 拦；打成普通 `<script>` 才能双击运行 |
| 迷宫 | 自写 DFS + 合批 | 网格碰撞简单，生成快，可复现 |
| 碰撞 | 胶囊体 + AABB 墙 + 地面高度 | 不引入物理引擎；台阶用斜坡近似 |
| 资产 | 程序化 + 少量 CC0 道具 | GLB 转 Base64 写进 `assets/*.js`；`LICENSES.md` 登记 |
| UI | DOM + Canvas 2D 小地图 | 中文字体、菜单、字幕好写 |
| 音频 | WebAudio 程序化 | 风雨、脚步、灯火、灯塔大门、主灯、结尾；零外部音频 |
| 测试 | Playwright + 诊断 API | 无头 Chrome 截图、状态断言、帧率采样 |

**渲染管线**：场景 Pass（不透明→透明）→ 阴影 Pass → 体积光/水面 → Bloom → ACES 色调映射 → 暗角/颗粒。

**场景组织**：墙体/地面按材质合并；火盆/石像/木箱用实例化；远景用雾裁剪；水面单独 Pass。

**结局镜头（重点）**：交互后切到 `ending` 状态，记录当前第一人称相机位姿，生成两条 Catmull-Rom 曲线（相机位置 + 注视点），5 个控制点：

1. 灯塔大门前（第一人称视角）→
2. 中央光井中段（垂直上升）→
3. 灯塔腰部（绕塔）→
4. 环塔石阵上空（俯视迷宫图案）→
5. 海岛外海远景（灯塔 + 石阵 + 大海同框）。

`t` 用 smoothstep 缓动，FOV 从 60 收到 45；镜头先抬头看主灯，再俯视石阵，最后拉远看海。路径经过光井与灯塔外侧，**保证不穿墙**；HUD 淡出、加 letterbox，标题与制作名单在最后 3 秒出现。

**外景与海面**：灯塔外立面、露天石阵、礁岛在进入迷宫前就建好；外海用大平面 Gerstner 波 + 远景简化 shader；船灯用发光点精灵；结局前预加载/预热，避免拉远时卡顿。

**性能目标**：三角形 ≤ 30 万、draw call ≤ 120、纹理显存 ≤ 200MB；画质档高/中/低，低画质保答辩。

**目录结构**

```
src/
  main.js            # 启动、循环、章节状态
  engine/            # 渲染器、构建、输入、资源、性能
  maze/              # DFS 生成、墙体合批、碰撞、区域
  world/             # 灯塔外景、礁岛、外海、露天石阵俯视
  render/            # 光照、阴影、体积光、水面、雨、后期
  game/              # 玩家、交互、火种、灯塔大门、ending 镜头、检查点、诊断
  ui/                # HUD、菜单、小地图、设置
  audio/             # WebAudio
assets/              # 纹理、GLB Base64、LICENSES.md
tests/               # Playwright
```
