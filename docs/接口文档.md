# 《长明：雾海迷宫》接口文档

> 版本：v0.4.1（迷宫规格定稿与合批）　｜　日期：2026-11-27　｜　维护：林子涵
> 本文档是模块之间的**契约**。接口变更必须同时改代码、改本文档，并在群里通知；不允许“先改代码再说”。

---

## 1. 基本原则

1. **单一入口**：`src/main.js` 负责组装模块，模块之间不互相 `import` 内部文件，只通过本文档定义的接口通信。
2. **单位统一**：1 单位 = 1 米；Y 轴向上；迷宫铺在 XZ 平面；角色默认朝向 `-Z`。
3. **角度**：代码内部用弧度，UI 显示用角度；所有时间单位是秒。
4. **坐标系**：迷宫格子 `(col,row)`，`col` 沿 +X，`row` 沿 +Z；格子中心由 `maze.cellCenter(col,row)` 给出。
5. **不暴露内部实现**：`Maze` 只暴露查询/碰撞方法，不暴露 DFS 数组；`Renderer` 只暴露场景、相机、渲染与画质开关。
6. **可诊断**：所有关键状态都能通过 `window.changming` 读取，方便 Playwright 回归和答辩排查。
7. **可降级**：WebGL2 不可用、shader 编译失败、帧率过低时，必须有明确的降级路径，不能白屏。

## 3. 启动顺序

`src/main.js` 的固定顺序（后续实现按此接入）：

```js
const canvas = document.querySelector('#scene')
const events = createEventBus()

const state = createGameState({ seed: readSeedFromURL(), quality: 'high' })
const renderer = createRenderer(canvas, { quality: state.quality })
const maze = createMaze({ seed: state.seed, loopRate: 0.12 })
state.checkpoint = maze.getStart()
const world = createWorld({ scene: renderer.scene, maze, quality: state.quality })
const player = createPlayer({ camera: renderer.camera, maze, domElement: canvas, state })
const interaction = createInteraction({ player, world, state, events })
const audio = createAudio()
const ending = createEnding({ scene: renderer.scene, camera: renderer.camera, player, world, renderer, state, events })
const ui = createUI({ state, events, maze, player, renderer, ending, audio })

renderer.start((dt) => {
  if (state.phase === 'playing') {
    player.update(dt)
    interaction.update(dt)
    world.update(dt)
  } else if (state.phase === 'ending') {
    ending.update(dt)
  }
  ui.update(dt)
  audio.update(dt)
})
```

> 顺序不能乱：`Renderer` → `Maze` → `World` → `Player` → `Interaction` → `Ending` → `UI`。

## 5. 模块接口

### 5.0 状态 `createGameState(options)`

```js
/**
 * @param {{seed:number, quality?:Quality}} options
 * @returns {GameState}
 */
const state = createGameState({ seed: 20261205, quality: 'high' })
```

初始值：`phase='title'`、`collected=0`、`seedIds=[]`、`checkpoint={col:0,row:0}`（`main.js` 拿到 maze 后改成 `maze.getStart()`）、`gateUnlocked=false`、`endingStarted=false`。
只有 Interaction / Ending / UI 允许改状态；其他模块只读。

### 5.1 事件总线 `createEventBus()`

```js
const events = createEventBus()
const off = events.on('seed:collect', (payload) => {})
events.emit('seed:collect', { id: 'seed-1' })
off()
```

| 事件 | payload | 生产者 | 消费者 |
| --- | --- | --- | --- |
| `seed:collect` | `{ id: string }` | Interaction | UI / Audio / World |
| `gate:unlock` | `{}` | Interaction / State | World / UI / Audio |
| `ending:start` | `{}` | Interaction / Ending | UI / Renderer / Audio |
| `ending:complete` | `{}` | Ending | UI |
| `quality:change` | `{ quality: Quality }` | UI | Renderer |
| `feature:toggle` | `{ name: string, enabled: boolean }` | UI | Renderer |
| `audio:play` | `{ name: string }` | 任意 | Audio |

### 5.2 迷宫 `createMaze(options)`

```js
/**
 * @param {{seed:number, loopRate?:number}} options
 * @returns {Maze}
 */
const maze = createMaze({ seed: 20261205 })
```

```js
/**
 * @typedef {Object} Maze
 * @property {15} size                 // 第二周定稿：固定 15×15
 * @property {number} seed
 * @property {number} loopRate
 * @property {MazeCell[][]} cells
 * @property {{row:number,col:number,world:Vec3}} entrance
 * @property {SeedSpec[]} spawnPoints
 */
```

约束：

- **迷宫规格已定稿为 15×15、4m 格、4.5m 墙高、0.62m 墙厚**；不再提供 19×19 运行时选项；
- 相同 `seed` 必须生成完全相同的迷宫、火种位置和区域划分；
- 碰撞通过 `world.collision` / `world.resolveMovement()` 查询；
- 迷宫生成不依赖渲染，可单独在 Node/测试里跑。

### 5.2A 迷宫网格 `buildMazeMesh(options)`

`buildMazeMesh` 将 `createMaze()` 的逻辑数据转换为可加入场景的 Three.js 对象。它只构建迷宫本体，不负责灯塔、外岛、玩法火种或 HUD。

```js
import {
  createMaze,
  createMazeMaterials,
  buildMazeMesh,
} from './src/world/index.js'

const maze = createMaze({ seed: 20261205, loopRate: 0.12 })
const materialBundle = createMazeMaterials({
  seed: maze.seed,
  renderer,
})
const mazeMesh = buildMazeMesh({
  maze,
  materials: materialBundle.materials,
  seed: maze.seed,
})

scene.add(mazeMesh.group)
```

输入：

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| `maze` | `Maze` | 是 | `createMaze()` 的返回值 |
| `materials` | `MaterialBundle` | 是 | 至少包含 `wall`、`wallCaps`、`floor`、`boundaryStone`、`water`、`moss`、`gold` |
| `seed` | `number` | 否 | 墙体高度微扰的独立随机种子；默认使用 `maze.seed` |

输出：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `group` | `THREE.Group` | 名称固定为 `StoneMaze`，包含墙体、墙帽、地面、中庭、水道和外圈残柱 |
| `segments` | `WallSegment[]` | 224 个左右的唯一墙段，含 `axis`、区域、位置、厚度和最终高度 |
| `wallMeshes` | `Record<RegionId, THREE.InstancedMesh>` | 按区域拆分的墙身实例 |
| `caps` | `Record<RegionId, THREE.InstancedMesh>` | 按区域拆分的墙帽实例 |
| `bases` | `THREE.InstancedMesh` | 所有墙段共用的基础石座 |
| `wallCount` | `number` | 唯一墙段数量 |
| `batching` | `object` | 批次区域、绘制对象数、实例化 Mesh 数等统计 |

材质分组与合批规则：

1. **墙身**：四区域各一个 `InstancedMesh`，共享 `BoxGeometry`；每个实例通过矩阵设置长度、高度和方向。
2. **墙帽**：四区域各一个 `InstancedMesh`，颜色区分区域；墙帽不进入阴影 Pass，墙体主体负责外轮廓阴影。
3. **墙基**：全部墙段共用一个 `InstancedMesh` 和 `boundaryStone` 材质。
4. **地面**：按区域各一个 `InstancedMesh`；中央 3×3 净空区不重复铺格，改为整块抬高平台。
5. **水院**：水道、月池、芦苇分别实例化；透明水面与不透明芦苇保持独立材质。
6. **中庭**：5 级台阶、4 条边缘、16 条罗盘金线、2 条扶手分别实例化；外圈残柱使用一个实例批次。
7. **迷宫局部合批**：允许烘焙的中庭实例与平台、刻线等静态 Mesh 在 `StoneMaze` 内部再次按材质合并，确保单独使用 `buildMazeMesh()` 时迷宫绘制对象不超过 40。
8. **世界级静态合批**：只合并不透明、无动画、无 `userData.noMerge` 的静态 Mesh；动态门扇、火盆、火光、海面、船灯和火种不参与。材质相同的跨地标对象会合并成一个静态批次。
9. **动态实例批**：11 条远景船合并为一个动态 `InstancedMesh`；7 处火盆火焰也合并为一个动态批次，每帧只更新实例矩阵。
10. **可复现性**：同 seed 的墙段数、实例矩阵、材质区域、火种格和区域划分必须完全一致。

验收数据（默认 seed `20261205`，可用 `npm run measure:world` 复测）：

- `buildMazeMesh()` 单独输出 22 个绘制对象，其中 18 个实例批次；
- 世界场景 53 个网格节点、23 个实例批次，约 7.59 万场景三角形；
- B 的静态合批输入 215 个 Mesh，输出 22 个材质批次；
- Chromium / Edge 1440×900 稳定测试帧：高画质 125 draw calls，低画质 72；
- 入口首帧仍因阴影与后处理预热较高，性能比较统一取画质稳定后的固定机位数据。

同 seed 回归：

```bash
npm run test:maze
```

测试覆盖 15×15 固定规格、同 seed 完全一致、不同 seed 有差异、100 个种子的可达性与三火种分布。

### 5.5 交互 `createInteraction(options)`

> v0.2 已在 `src/game/interaction.js` 落地第一人称预览版。最终 D 模块仍可保持
> `tryInteract()` / `update()` / `getFocus()` 方法不变，替换内部控制器即可。

当前实现签名：

```js
const interaction = createInteraction({
  camera, cameraRig, input, world, fireSeeds, state, events, hud,
})
```

当前行为：

- 约 2.0 m 内自动聚焦，不要求准星精确压住火种；
- 2.0–4.5 m 内使用宽视线锥和墙体视线采样；
- 聚焦时火种变大、光晕增强并显示 `E` 提示、目标区域和距离；
- `E` 拾取后更新 `state.collected / state.seedIds`，发 `seed:collect`，播放上升缩小动画；
- 三枚集齐后 `gateUnlocked=true` 并发 `gate:unlock`；
- 灯塔大门 2.65 m 内可聚焦；未集齐显示剩余数量，集齐后调用 `world.setDoorOpen(1)` 与 `world.setBeaconIntensity(1)`。

调试方法：`window.changming.teleportToSeed(0..2)`。

```js
/**
 * @typedef {Object} Interactable
 * @property {string} id
 * @property {Vec3} position
 * @property {number} radius
 * @property {()=>string} getPrompt
 * @property {()=>void} onFocus
 * @property {()=>void} onBlur
 * @property {()=>void} interact
 */
```

```js
/**
 * @param {{player:Player, world:World, state:GameState, events:EventBus}} options
 * @returns {{update:(dt:number)=>void, register:(i:Interactable)=>void, unregister:(id:string)=>void}}
 */
```

行为：

- 每帧从相机中心做射线/距离检测，最近的可交互物进入 focus；
- `E` 触发 `interact()`；
- 火种交互：`state.collected++`、`state.seedIds.push(id)`、`events.emit('seed:collect')`、`world.collectSeed(id)`；
- 集齐 3 枚后 `state.gateUnlocked = true`，`events.emit('gate:unlock')`；
- 灯塔大门交互：未集齐时提示“还差 N 枚火种”；集齐后 `ending.start()`。

### 5.6 渲染 `createRenderer(canvas, options)`

```js
/**
 * @param {HTMLCanvasElement} canvas
 * @param {{quality:Quality}} options
 * @returns {Renderer}
 */
```

```js
/**
 * @typedef {Object} Renderer
 * @property {THREE.Scene} scene
 * @property {THREE.PerspectiveCamera} camera
 * @property {(update:(dt:number)=>void)=>void} start
 * @property {()=>void} resize
 * @property {(quality:Quality)=>void} setQuality
 * @property {(name:string,enabled:boolean)=>boolean} setFeature
 * @property {((dt:number)=>void|null)=>void} setRenderCallback  // 后处理管线接管每帧渲染
 * @property {(handler:(quality:Quality)=>void)=>()=>void} onQualityChange
 * @property {()=>{fps:number,drawCalls:number,triangles:number,quality:Quality,renderMode:'direct'|'pipeline'}} getStats
 * @property {()=>void} dispose
 */
```

`setFeature` 支持的 name：

`shadow` / `lantern` / `volumetric` / `water` / `rain` / `bloom` / `pbr`
（`ssao` 预留，未实现时返回 `false`）

画质档从 v0.3 起是**参数 + 特性组合**双降级，切档时 `renderer.setQuality()` 会依次触发
`onQualityChange` 订阅者（渲染管线），由管线同步阴影贴图、水面细分、Bloom 参数并应用下表：

| 画质 | shadow | lantern | volumetric | water | rain | bloom | pbr |
| --- | --- | --- | --- | --- | --- | --- | --- |
| high | ✅ | ✅ | ✅ | 默认关 | 默认关 | ✅ | ✅ |
| medium | ✅ | ✅ | ❌ | 默认关 | 默认关 | ✅ | ✅ |
| low | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ | ❌（Blinn-Phong） |

- `water` 默认关闭：主场景外海仍由 B 的 `ocean` 兜底；打开后隐藏 B 海面、显示 C 的 Gerstner 水面。
- `rain` 默认关闭：打开后显示相机局部雨丝和地面涟漪，不依赖音频系统。
- 切档会覆盖手动特性开关，UI 需要在切档后重新读取 `getDiagnostics().features`。
- URL 调试参数（不改 UI，供答辩/回归）：`?quality=low&water=1&rain=1&bloom=0`，
  特性名支持 `shadow/lantern/volumetric/water/rain/bloom/pbr`，值 `1/0`。

主场景接入方式（`src/main.js`）：

```js
const pipeline = createRenderPipeline({ scene, camera, renderer, engine: renderer, quality, features })
renderer.setRenderCallback((dt) => pipeline.render(dt))
renderer.onQualityChange((quality) => {
  pipeline.setQuality(quality)
  pipeline.resize(window.innerWidth, window.innerHeight, window.devicePixelRatio)
})
```

旧 `atmosphere-legacy` 只保留夜空/星/月/雾，光源全部移除；玩家灯笼由管线 `lighting.lantern`
取代，`window.__changming.playerLantern.getLight()` 返回同一盏 `SpotLight` 以兼容旧测试。

### 5.7 结局 `createEnding(options)`

```js
/**
 * @param {{scene:THREE.Scene, camera:THREE.PerspectiveCamera, player:Player, world:World, renderer:Renderer, state:GameState, events:EventBus}} options
 * @returns {Ending}
 */
```

```js
/**
 * @typedef {Object} Ending
 * @property {()=>void} start
 * @property {(dt:number)=>void} update
 * @property {()=>void} skip
 * @property {()=>boolean} isComplete
 */
```

约定：

- `start()` 只在 `state.collected === 3 && state.gateUnlocked` 时可调用；
- 调用后 `state.phase = 'ending'`、`player.setEnabled(false)`、HUD 淡出；
- 镜头路径 5 个控制点：大门前 → 光井 → 塔腰 → 石阵上空 → 外海远景；
- 总时长 12~15 秒；`skip()` 只用于调试/答辩兜底，正常演示不跳过；
- `isComplete()` 为 true 后 UI 显示标题/制作名单，不再回到第一人称。

### 5.10 诊断 `window.changming`

```js
window.changming = {
  version: '0.1.0',
  getState: () => ({ ...state, seedIds: [...state.seedIds] }),
  getDiagnostics: () => ({ webglVersion, quality, features, fps, drawCalls, triangles, seed, collected, phase, renderMode }),
  getPipelineDiagnostics: () => ({ quality, features, qualityFeatures, lightingModelMaterials, renderTarget }),
  teleport: (cell) => player.teleport(cell),
  giveSeeds: (n = 3) => { /* 调试用：直接收集 n 枚 */ },
  openGate: () => { /* 调试用 */ },
  triggerEnding: () => ending.start(),
  setQuality: (q) => renderer.setQuality(q),
  setFeature: (name, enabled) => renderer.setFeature(name, enabled),
  screenshotReady: () => document.body.dataset.ready === 'true'
}
```

约束：

- `getState()` / `getDiagnostics()` 必须返回可 JSON 序列化的对象；
- `triggerEnding()` 只用于测试/答辩，正常流程必须由大门交互触发；
- Playwright 通过 `screenshotReady()` 等待首帧，不能靠固定 sleep。

## 7. 错误与降级

1. **WebGL2 不可用**：显示“当前浏览器不支持 WebGL2”的提示，不抛异常；
2. **shader 编译失败**：`console.error` 输出日志，降级到基础材质，画质切 `low`；
3. **`file://` 限制**：不使用 `fetch`/ESM 直连；GLB 走 Base64，three.js 走 IIFE bundle；
4. **帧率过低**：自动降 pixelRatio → 关雨 → 关体积光；不改变玩法与结局；
5. **本地存储不可用**：检查点只存内存，`localStorage` 用 `try/catch` 包裹。

## 8. 接口变更流程

1. 提 PR，标题 `docs(api): ...`，同时改代码与本文档；
2. 模块负责人 + 组长各 1 个 approve；
3. 群里通知受影响的人（尤其是 `Maze`、`Player`、`Ending`）；
4. 合并后 `main` 立即跑一次构建与冒烟测试；
5. 破坏性变更升版本号（v0.1 → v0.2），并在 PR 描述写迁移方法。
